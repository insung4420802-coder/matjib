# v22 새 기능 로컬 미리보기

이 경로는 로컬 실험용 화면입니다. 별도의 운영 화면 `/tools/`와 Vercel API 연결은 [V22-RELEASE.md](../../V22-RELEASE.md)를 참고하세요. 아래의 로컬 서버·메모리 저장 설명은 `/preview/v22/`에만 적용됩니다.

## 실행

저장소 루트에서 Node.js로 `node preview/v22/server.mjs`를 실행한 후 `http://127.0.0.1:4173/preview/v22/`를 엽니다. 이 컴퓨터에서만 접속할 수 있으며 서버를 종료하면 접속할 수 없습니다. 다른 사람이 인터넷으로 접속하는 공개 배포가 아닙니다.

## 지금 실제로 동작하는 부분

- 모임방 생성, 최대 6명 참여, 후보 2~5곳, 3단계 투표, 실제 참여자 전원의 수용 여부 집계, 방장 확정, 방 삭제. ‘다른 참여자로 열기’로 같은 컴퓨터의 여러 탭에서 테스트합니다.
- 메뉴 사진 최대 5장 선택·추가·삭제·중복 사진 제외, 원본 장당 20MB까지 브라우저 내 순차 JPEG 최적화, 별도 카메라 촬영 입력, 최적화 사진 확대 확인. 가상 예시 메뉴 로드, 직접 메뉴·가격 입력 및 수정, 인원·예산·수량에 따른 주문 조합과 합계 계산, 현지어 메뉴명과 수량 주문 카드.
- 출발지·후보 좌표에 따른 실제 직선거리 계산, 가장 먼 사람의 부담이 작은 후보 정렬, 중간 지점 비교, 후보를 모임 생성 화면으로 넘기기.

## 로컬 실행과 Vercel 연결의 구분

- 이 로컬 서버의 모임방 정보는 서버 메모리에만 저장하며 재시작 시 없어집니다. 48시간 만료, 방장 삭제, 참여자 토큰 접근 제어가 있습니다. 별도 Vercel `/tools/` 화면에는 영속 Redis 저장소를 연결했으며 실제 미리보기 검증 결과는 아래에 기록했습니다.
- 메뉴 사진의 실제 AI 판독은 서버 환경에 `ANTHROPIC_API_KEY`가 있을 때만 활성화합니다. `.env`나 운영 비밀키를 자동으로 읽어오지 않습니다. 기본 모델은 `claude-haiku-4-5`이며 `ANTHROPIC_MODEL`로 기존 모델을 유지할 수 있습니다. 키가 없으면 분석 완료를 꾸미지 않고 예시·직접 입력만 제공합니다.
- 사진은 사용자가 ‘전체 분석’ 버튼을 누를 때만 선택한 전체 사진을 한 요청으로 Anthropic에 전송합니다. 사진마다 자동 호출하지 않습니다. 앱에서는 사진을 디스크에 저장하지 않습니다. 외부 제공자의 데이터 처리 정책은 별도로 적용됩니다. 판독 오류 확인과 가격 수정 후 주문 계획을 만들어야 합니다.
- 사진별 원문 메뉴명이 같은 항목을 병합하고 출처 사진 번호를 보존합니다. 가격 차이·미확인 가격 혼합은 가격을 비워 두고 사용자에게 선택·직접 입력을 요청합니다. 미해결 메뉴는 주문 조합에서 제외합니다. 서로 다른 통화는 자동 환산하지 않습니다. ‘여러 페이지 예시’는 실제 사진을 분석하지 않고 이 흐름을 체험하는 가상 자료입니다.
- 길찾기·실제 이동시간·실시간 교통 API는 연결하지 않았으며, 이 로컬 화면 자체에서 새 식당 검색 API를 호출하지 않습니다. 가상 식당은 실제 식당 추천이 아닙니다. Vercel `/tools/`에는 기존 검색 후보를 가져오는 연결을 추가했고, 해외 검색 후보의 모임 전달을 실제 미리보기에서 확인했습니다.
- 알레르기 안전, 현재 가격·판매 여부·세금·봉사료 포함 여부, 실제 1인분 양을 보증하지 않습니다.

## 비용·보호

로컬 기본 실행에는 외부 유료 API 호출이 없습니다. API 키를 연결한 경우에만 사진 분석 1회당 과금이 발생합니다. 사진 최대 5장, 원본 장당 20MiB, 최적화 후 사진당 약 614KiB·전체 3MiB, 페이지당 최대 20개·합친 메뉴 최대 60개, 사진 분석 분당 3회, 출력 최대 6,000토큰·분석 35초 제한이 있습니다. 누락·잘림·불확실한 가격은 안내합니다. 별도 Vercel `/tools/` API에는 운영·미리보기를 합친 기본 월 20회 분석 요청 제한을 추가했습니다. 사진 20장이 아닌 요청 20회이며, 기존 검색 비용까지 합친 월 5천 원을 보장하는 한도는 아닙니다.

사진은 원본을 업로드하지 않고 기기에서 한 장씩 변환합니다. JPEG·PNG·WebP는 처음 512KiB의 헤더에서 해상도를 먼저 확인해 64MP를 넘는 사진을 해독 전에 거절합니다. HEIC는 이 사전 해상도 검사 대상이 아니며 브라우저 지원과 기기 메모리에 의존합니다. 긴 변 1,568px부터 JPEG 품질 0.9 → 0.84 → 0.78 순서로 시도하고, 필요 시 긴 변 1,400px·1,200px까지 줄입니다. 이 하한에서도 용량을 맞출 수 없으면 무리하게 압축하지 않고 구역별 재촬영을 안내합니다. 작은 글씨 판독은 보장하지 않으며 사용자가 최적화한 사진을 확대 확인할 수 있습니다. EXIF 등 원본 메타데이터는 캔버스 재출력에 포함하지 않습니다.

HEIC/HEIF는 브라우저의 기본 디코더가 지원할 때만 JPEG로 변환합니다. 미지원 브라우저에서는 JPEG/화면 캡처를 안내하며, 별도 외부 변환 서버로 원본을 보내지 않습니다. 실제 iPhone/Android 촬영·회전은 실기기 확인이 필요합니다.

Vercel의 4.5MB 요청 한도를 고려해 사진 합계를 3MiB로 줄이고, 최종 base64 JSON과 로컬 서버 입력을 각각 4,200,000바이트로 제한했습니다. 새 API는 Vercel 미리보기에서 연결·검증했지만 운영 main에는 아직 병합하지 않았습니다. 근거: [Vercel 제한](https://vercel.com/docs/functions/limitations), [Safari HEIC 지원](https://webkit.org/blog/14205/news-from-wwdc23-webkit-features-in-safari-17-beta/), [캔버스 JPEG 출력](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/toBlob).

서버는 127.0.0.1에만 바인딩하고 요청 Host/Origin을 검사하며 허용된 공개 파일만 제공합니다. 모임 참여 토큰은 링크에 포함하지 않고 탭의 sessionStorage에 저장합니다.

## 초기 로컬 검증 기록 (과거 단계)

- 당시 기존 121개와 새 기능 65개, 총 186개 자동 검사가 통과했습니다. 사진 최적화는 모의 디코더/인코더로 헤더 해상도 사전 검사·품질 순서·용량·메모리 해제·실패 처리·본문 한도를 검사했습니다. 아래 항목도 초기 로컬 화면의 검증 기록입니다.
- 여러 사진을 한 번에 선택하고 나눠 추가해 총 5장에 도달하면 추가 선택이 비활성화됨을 브라우저에서 확인. 개별 삭제 후 4장으로 줄면 다시 추가 가능.
- 4장 상태에서 2장 추가 시 제한 안내와 기존 사진·주문 결과 보존 확인. 사진 전체 삭제 시 메뉴·주문 결과 초기화 확인.
- 여러 페이지 가상 예시에서 중복 메뉴 병합, 1,250/1,350 JPY 가격 선택, 선택 후 3인·4,000 JPY 예산 → 3,600 JPY 조합 생성 확인. 360px 화면에서 가로 넘침 없음.
- 브라우저에서 두 탭의 서로 다른 참여자 투표, 미응답 구분, 모두 동의한 후보 표시를 확인.
- 화면 내 확인창을 통한 최종 식당 결정 확인. 기본 브라우저 확인창은 사용하지 않음.
- 가상 메뉴 3인·4,000 JPY 예산 → 3,500 JPY 조합 생성. 수량 증감 시 6,900 JPY 및 예산 초과 표시, 현지어 주문 카드 확인.
- 첫 출발지를 강남역에서 홍대입구역으로 변경했을 때 거리와 추천 순서 갱신, 선택 후보를 모임 생성으로 전달 확인.
- 360px 화면에서 세 기능의 가로 넘침 없음, 메뉴 편집은 접기/펼치기로 축약.
- 이 초기 로컬 단계에서는 실제 사진 AI 판독·외부 기기 동시 접속을 검증하지 않았습니다. 이후 실제 AI·영속 저장소 검증은 다음 항목과 구분합니다. 길찾기 API는 여전히 연결하지 않았습니다.

- Vercel 미리보기 배포 `ce104ce`: **Ready**, 함수 **10개**, **Node.js 24** 확인. **운영 main은 아직 미병합이며 운영 배포·운영 QA는 대기 중입니다.** 운영 v21 기준은 `5305218a8409c51334f926164c453bd81a8a6a44`입니다.
- GitHub 연결 도구 대신 로그인된 인앱 브라우저에서 GitHub 웹 작업으로 파일을 업로드했습니다. 원격 `v22-smartphone-menu-tools` 브랜치에 업로드한 변경으로 미리보기 배포를 검증했습니다.
- 사용자 승인 후 전용 Upstash Free 저장소를 Vercel에 연결했습니다. `/tools/`용 영속 모임방 API, 프로젝트 공통 월 20회 메뉴 분석 요청 제한, 기존 검색 후보 전달 코드를 포함합니다.
- 가상으로 만든 메뉴판 사진 2장을 **실제 Haiku API에 한 요청으로 전송**해 메뉴 6개와 USD 가격을 읽었습니다. 주문 조합과 현지어 주문 카드도 확인했습니다. 모의 AI 응답이 아닌 실제 분석 1회이며 공유 월 한도에 포함됩니다.
- 같은 브라우저의 두 탭에서 방장·참여자로 영속 Redis 모임방 생성·참여·투표·합의·최종 확정, 다른 탭의 확정 상태 동기화를 확인했습니다. 서로 다른 실기기 간 동시 접속을 검증한 것은 아닙니다.
- 기존 해외 검색에서 도쿄역 라멘 후보 20곳과 평점·후기 표시를 확인했습니다. 이 중 후보 3곳을 새 탭의 모임 생성 화면으로 가져오는 흐름도 확인했습니다.
- 해외 검색 후보 20곳을 거리 비교 링크로 새 탭에 전달했습니다. 테스트 출발지 `(35.68, 139.76)`, `(35.69, 139.78)`를 직접 입력한 뒤 실제 식당 20곳의 직선거리 순위와 참여자별 거리 표시를 확인했습니다. 실제 교통 경로·이동시간 검증과는 구분합니다.
- 국내 미리보기는 카카오 등록 도메인 제한으로 SDK 로드가 실패했습니다. 운영 도메인에서 병합·배포 후 국내 검색을 별도 확인해야 합니다.
- 휴대폰 실기기 촬영·HEIC/HEIF·사진 회전은 아직 검증하지 않았습니다.
