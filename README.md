# 임슐랭 가이드

감성 키워드로 검색하면, **광고를 걸러낸 진짜 후기만으로 별점을 매겨** 근처 맛집을 추천하는 가족용 도구.
네이버 검색과의 차별점 = "협찬/체험단 후기를 판별해 걸러내고, 진짜 후기의 만족도로 임슐랭 별점(1~5)을 산정".

## v18 국내 배달앱 버튼 제거

- 특정 음식점 검색 화면으로 연결되지 않는 국내 배민·쿠팡이츠 버튼을 제거한다.
- 국내는 검증 후기에서 실제 배달 관련 표현을 찾은 음식점에만 `후기에서 배달 언급` 정보 배지를 표시한다. 단순 배달 검색만으로는 별도 영역을 만들지 않는다.
- 해외 Uber Eats와 동남아 GrabFood는 웹에서 배달 가능 여부를 확인할 수 있어 기존 버튼을 유지한다.
- 국내 배달앱이 공식 음식점 딥링크나 제휴 API를 제공하기 전에는 주문 연결 기능을 다시 추가하지 않는다.

## v17 배달앱 연결

- 원래 검색어에 `배달`, `딜리버리`, `delivery`, 배달앱 이름 등이 있을 때만 결과 카드에 배달앱 영역을 표시한다.
- 일반 검색에서도 이미 수집한 후기의 플랫폼명·실제 배달 주문 표현을 확인한다. 강한 근거 1건 또는 서로 다른 후기 2건이 있는 음식점에만 `후기에서 배달 언급` 영역을 표시하며, 배달 불가·중단 표현은 제외한다.
- 국내 결과는 배민·쿠팡이츠, 해외 결과는 Uber Eats를 연결한다. 태국·베트남·싱가포르 등 동남아 결과는 GrabFood를 우선 연결한다.
- 버튼을 누르면 `음식점명 + 지점 주소`를 복사한다. 공개 음식점 조회 API가 아니므로 실제 입점·배달 가능 여부는 열린 앱에서 최종 확인한다.
- 기존 검색·지도·AI 호출을 추가하지 않으며 회귀 검사는 `tests/v17-delivery-links.test.mjs`에 있다.

## v16 결과 제어·지도 재검색

- 결과를 추천순·가까운 순·후기 많은 순으로 정렬한다. 해외는 가격 낮은 순과 `₩/₩₩/₩₩₩+` 가격 필터도 제공한다.
- `영업 중만` 필터를 추가했다. 해외는 검색 응답을 바로 사용하고, 국내는 사용자가 필터를 누를 때만 영업 정보를 확인해 하루 동안 기기에 캐시한다.
- 각 카드에서 `관심 없음` 또는 `잘못된 결과` 사유를 선택하면 다음 검색에서도 숨긴다. 숨긴 곳 버튼으로 현재 검색의 결과를 복원할 수 있다.
- 카카오·구글 지도를 움직인 뒤 `이 지역 재검색`을 누르면 지도 중심 좌표로 다시 찾는다. 기존 메뉴 변환을 재사용해 Claude 호출은 추가하지 않는다.
- 국내는 신뢰할 가격대 데이터가 없어 가격 필터를 표시하지 않는다.

## v15 지도 화면 동선 개선

- `목록/지도` 전환을 결과 수 바로 아래의 독립된 영역으로 올려 한눈에 찾을 수 있게 했다.
- 별점 필터 다음에 1등 추천을 보여주고, 지도 모드에서는 1등 카드 바로 아래에 지도를 배치한다.
- 목록 카드의 `지도에서 보기`를 누르면 해당 핀 정보창을 연 뒤 지도 영역까지 자동으로 스크롤한다.
- 지도 핀의 첫 클릭은 음식점 이름·평점을 보여주고, 같은 핀을 두 번째로 클릭해야 목록의 해당 카드로 이동·강조한다.
- 화면 배치와 클릭 단계만 바꿨으며 지도·검색 API 호출 수는 늘지 않는다.

## v14 지도·목록 연결 개선

- 지도에서 현재 내 위치는 파란 원, 사용자가 정한 위치·검색어에서 감지한 위치는 보라색 마름모로 구분한다.
- 지도 위 안내에 기준 위치의 종류와 이름을 표시한다.
- 맛집 핀과 목록 카드를 양방향으로 연결한다.
- 각 목록 카드의 `지도에서 보기`를 누르면 지도로 전환해 해당 핀과 정보창을 연다.
- 기존 카카오·구글 지도 위에서 동작하므로 지도 API 호출 횟수는 늘지 않는다.

## v13 검색·후기 개선

- `얼큰한 국물`처럼 메뉴가 정해지지 않은 검색은 바로 넓게 검색하지 않고, 해장국·짬뽕·마라탕 등 최대 12개의 구체 메뉴 후보를 먼저 보여준다.
- 사용자가 후보 하나를 누르면 장소검색에는 그 메뉴 하나만 전달해 결과 집중도를 높인다. 목록에 없으면 직접 메뉴를 입력할 수 있다.
- 구체 메뉴(`짬뽕`, `소바`)는 선택 단계를 생략하고 기존처럼 바로 검색한다. 국내·해외 모두 적용된다.
- 국내 카드의 진짜 후기 노출은 3→최대 6개, 해외는 현지 2→4개와 한국인 2→4개로 최소 2배 확대했다.
- 네이버 원자료는 호출당 30→50개, 구글 현지 리뷰는 장소당 최대 3→5개를 받아 더 많은 후기 후보를 확보한다. API 호출 횟수와 광고 판정 Haiku 최대 배치는 늘리지 않았다.

## v12 사용자 기능

- 검색 결과에서 최대 3곳을 `비교 담기`로 선택해 별점·거리·후기 근거·메뉴 적합도·주소를 한 화면에서 비교한다.
- 선택한 후보 또는 현재 상위 3곳을 카카오톡/공유 메뉴로 한꺼번에 공유한다. 공유 메뉴가 없으면 목록 전체를 클립보드에 복사한다.
- 즐겨찾기에 사용자 폴더를 만들고, 맛집마다 `다녀왔어요` 표시와 최대 300자의 방문 메모를 저장한다.
- 세 기능은 현재 검색 결과와 브라우저 `localStorage`를 사용하므로 추가 API 호출이나 AI 비용이 없다.
- 폴더와 방문 메모는 현재 기기에만 저장된다. 브라우저 데이터 삭제나 기기 변경에 대비한 계정 동기화는 향후 서버 저장소가 필요하다.

## v11 별점 로직 (핵심)

국내 별점은 이제 **광고 판별**과 **후기 만족도**를 분리한다. 추가 AI 호출은 없다.

1. **후기 만족도 (satisfaction)** — 진짜 후기의 맛·만족·재방문과 실망·불친절·재방문 거부 신호를 분석한다. 국내 별점의 직접 근거다.
2. **진짜후기 밀도 (authenticity)** — 협찬 아닌 후기 비율. 광고밭의 추천 순위 상한을 누른다.
3. **후기 양·최신성** — 증거가 충분하고 최근인지 평가한다.
4. **키워드 적합도** — 가게명·업종과 진짜 후기만으로 검색 의도 일치 여부를 확인한다.

검색은 정확 메뉴부터 시작하며 유효 후보가 부족할 때만 유사 메뉴와 큰 분류로 넓힌다. 네이버 결과는 제목의 상호명 또는 요약의 전체 상호명이 확인되는 글만 사용해 다른 지점·목록성 글을 제외한다.

- 진짜 후기 0~1개: 별점 없음(`자료 부족`)
- 진짜 후기 2개: 최고 4점
- 진짜 후기 3~4개: 최고 4.5점
- 국내 1등: 진짜 후기 3개 이상인 검증 성공 장소만
- 판정 API 실패: 장소는 보여주되 별점·진짜후기·1등은 숨김
- 정확 메뉴가 없을 때: `1등 맛집`으로 단정하지 않고 `비슷한 메뉴 중 추천`으로 표시

광고 판별은 2단계: (1) 휴리스틱(협찬/원고료/체험단 등 문구 + 내돈내산 신호)으로 즉시 판정,
(2) `ANTHROPIC_API_KEY`가 있으면 애매한(확률 0.3~0.7) 후기만 골라 Claude가 배치 재판정 → 정확도 향상.
키가 없거나 실패해도 (1)만으로 정상 작동.

## 구조

```
├── index.html          # 검색 UI + 카카오 장소검색 + 별점 렌더 + 즐겨찾기/히스토리
└── api/
    ├── keywords.js     # 감성어 → 실제 메뉴 키워드 변환 (Claude)
    ├── blog.js         # 네이버 블로그 원시 후기 수집
    ├── judge.js        # 임슐랭 판정 (휴리스틱 + Claude 재판정)
    └── lib/score.js    # 별점 엔진 (4축 결합)
```

## 설정 (변경 없음)
- `index.html` 상단 `KAKAO_JS_KEY`에 카카오 JavaScript 키
- Vercel 환경변수: `NAVER_CLIENT_ID`, `NAVER_CLIENT_SECRET`, `ANTHROPIC_API_KEY`(선택), `ANTHROPIC_MODEL`(선택)
- 선택: `APP_ACCESS_KEY`를 설정하면 최초 접속 시 공유용 접근 코드를 한 번 입력한다. 지인 외 API 무단 사용을 줄이는 용도다.
- 배포 도메인을 카카오/네이버 콘솔에 등록

## 비용
- 카카오/네이버: 무료 쿼터 범위에서 사용
- Claude: 검색당 키워드 변환 1회 + 국내의 애매한 후기 배치 판정 1회(필요할 때만). 메뉴 후보를 누르면 첫 변환 결과를 재사용하므로 AI 호출이 추가되지 않는다. 해외에서 목록에 없는 메뉴를 직접 입력한 예외 상황만 변환 1회가 추가될 수 있다.
- 해외 현지 리뷰 번역은 여러 검색어 중 첫 검색 결과에만 실행해 Haiku 호출을 최대 1회로 제한한다.
- Google Maps Platform은 2025-03부터 월 $200 일괄 크레딧이 아니라 SKU별 월간 무료 사용량 방식이다. Google Cloud에서 예산 알림과 API 쿼터를 반드시 설정한다.

## 한계
- 카카오맵/네이버 **평점 숫자는 공식 API로 제공되지 않아** 사용하지 않는다. 임슐랭 별점은 후기 신뢰도 기반 자체 지표다.
- 광고 판별은 네이버가 주는 제목+요약 텍스트 기반이라 100%는 아니다(본문 전체는 API 미제공).
- 후기 API는 서버리스 함수 경유라, 로컬에서 파일만 열면 별점/후기가 안 뜬다. `npx vercel dev` 또는 배포 후 테스트.

## 해외 모드 (신규)

왼쪽 상단 국내/해외 토글. 해외 선택 시:
- `api/keywords.js`가 "오사카 소바 맛집"을 지역(Osaka)+메뉴(soba/そば)로 분해 (한국어/영어 입력 모두 처리)
- `api/gplaces.js`가 구글 Places 텍스트 검색으로 현지 맛집+평점+리뷰 수집, 현지어 리뷰는 Claude가 한국어 번역
- `api/blog.js`로 한국인 블로그 후기도 병행 수집
- `api/judge-overseas.js` + `score.js`의 `evaluateOverseasPlace`가 구글 평점(베이지안 보정: 리뷰 적은 고평점=관광객 함정 배제) + 리뷰 수 + 한국인 화제성 + 적합도를 종합해 별점 산정
- 길찾기는 구글맵 연결

### 구글 Places API 설정
1. [console.cloud.google.com](https://console.cloud.google.com) → 프로젝트 생성
2. **Places API (New)** 사용 설정
3. 사용자 인증 정보 → API 키 생성
4. **결제 계정 연결 필수** (신용카드). SKU별 월간 무료 호출 한도와 현재 가격은 Google 공식 가격표에서 확인
5. Vercel 환경변수 `GOOGLE_MAPS_API_KEY`에 등록

### 해외 지도 보기 (선택)
해외 모드의 [지도] 토글을 쓰려면 브라우저용 구글맵 키가 별도로 필요합니다:
1. 구글 클라우드 콘솔 → API 라이브러리 → **Maps JavaScript API** 사용 설정
2. 사용자 인증 정보 → API 키 **새로 생성** (서버 키와 분리)
3. 키 제한: 애플리케이션 제한 = **웹사이트**, 배포 도메인(`https://앱이름.vercel.app/*`) 등록 + API 제한 = Maps JavaScript API
4. `index.html` 상단 `GOOGLE_MAPS_JS_KEY`에 입력
비워두면 해외 지도 보기만 꺼지고 나머지는 정상 작동합니다. 지도는 사용자가 지도 버튼을 눌렀을 때만 로드됩니다.
